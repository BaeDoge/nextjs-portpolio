## Background

Managing BUYMA listings involved repeatedly checking competitor prices and manually deciding whether a product price should be adjusted. As the number of listings grew, this took time and made it harder to apply consistent rules. It was also important to avoid reducing a price by more than an acceptable amount in a single run.

I built this tool to connect competitor price comparison and controlled price updates, using Google Sheets as the source for product URLs and execution records.

## End-to-end Workflow

~~~text
Product URLs from Google Sheets
        │
        ▼
Retrieve BUYMA competitor prices
        │
        ▼
Retrieve current BestShip listing price
        │
        ▼
Evaluate pricing rules
  ├── Is the listing already at or below the lowest competitor?
  ├── Is the target price valid?
  └── Is the reduction within the configured limit?
        │
        ▼
Preview and review eligible products
        │
        ▼
Submit BUYMA Product API update
        │
        ▼
Write Google Sheets / CSV history
~~~

## Pricing Rules

<TechStack items={["Python", "uv", "Playwright", "Google Sheets API", "BUYMA Product API", "pytest"]} />

The calculation is isolated as a pure function in pricing.py. Instead of blindly matching the lowest competitor price, the program evaluates the current price together with configurable limits.

    rows: [
      ["Current price is already at or below competitor minimum", "Keep the current price"],
      ["Target price = competitor minimum - delta", "Calculate the configured undercut"],
      ["Target price is zero or lower", "Reject the proposed change"],
      ["Reduction exceeds max_change", "Reject the proposed change"],
      ["All checks pass", "Mark the listing as eligible for an update"]
    ]
  }}
/>

~~~python
target_price = competitor_min - delta
reduction = current_price - target_price

# current_price > competitor_min
# target_price > 0
# reduction <= max_change
~~~

delta is the amount to undercut the lowest competitor price. max_change is the maximum reduction allowed in one run. Both values are managed in config.yaml.

## Reliability and Verification

<CalloutBox type="warning">
  Automated tests use mocked HTTP responses and Google Sheets objects. Passing the test suite does not guarantee that an update will succeed against a live BUYMA account. Credentials, API permissions, listing status, and external service responses must still be checked in the operating environment.
</CalloutBox>

Time-sale listings can be excluded according to configuration. The scheduler also avoids forcing an execution when additional authentication or an external service issue interrupts the process, and records the outcome for review.

## AI-assisted Development and My Contribution

I used AI tools to refine pricing rules, identify edge cases, and improve the API integration and test scenarios. I made the decisions about the pricing policy and operating workflow. Cases such as listings already at the lowest price, invalid target prices, reductions above the configured limit, and time-sale products were explicitly separated and covered by tests.

## Takeaways

The most important part of this project was not the act of changing prices automatically. It was defining **when a change should happen and when the program should leave the price alone**. Automation that affects an external system needs preview steps, limits, execution history, and tests alongside the automation itself.
