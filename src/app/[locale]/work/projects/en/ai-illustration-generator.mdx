## Background

Generating one image from a prompt is only part of the challenge. For a short comic or a sequence of illustrations, the scenes need to follow a coherent direction, the visual style should remain recognisable, and the generated candidates need to be reviewed before they are composed.

I started this project to automate that workflow: plan a sequence of scenes from text, generate multiple image candidates for each scene, compare the results, and assemble selected images into a visual sequence. Recent experiments have focused on friendly animal characters such as dogs, cats, and rabbits, with simple shapes and restrained detail.

### 1. Scene Planning and Style Composition

The LLM turns the topic and scene information into a short sequence, then converts each scene into an image-generation description. A style is selected from code-defined presets, and shared positive and negative prompt elements are combined with the individual scene prompt to reduce visual drift.

### 2. Image Candidate Generation

The application runs a Diffusers Stable Diffusion XL pipeline on a local GPU. It generates multiple candidates for each scene and records the seed so that results can be reproduced under the same conditions. The model path, optional LoRA, and CPU offload behaviour can be configured for the local environment.

## Development Environment

The public repository uses Python 3.11, PyTorch, and Diffusers to run image generation on a CUDA-capable GPU. The default pipeline is based on SDXL, with support for specifying another checkpoint or a LoRA.

~~~bash
uv sync
python main.py check
~~~

Demo mode can be used to inspect the planning flow and image-generation output with test input. Actual image generation requires the model files and a correctly configured CUDA environment.

## Current Scope and Limitations

<CalloutBox type="warning">
  The public repository is an experimental implementation of an image-generation and scene-composition pipeline. Without a VLM, semantic image checking relies on CLIP ranking and basic quality checks. It also does not guarantee that a character's appearance, clothing, or proportions remain identical across multiple panels; reference-image conditioning and additional training for consistent characters remain areas for further experimentation.
</CalloutBox>

Some execution paths are built around a particular multi-panel content format, so this should not be considered a general-purpose image editor or a complete comic-production application. The current focus is to keep planning, candidate generation, image comparison, and panel composition as separate steps that can be improved independently.
