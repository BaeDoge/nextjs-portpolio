## 프로젝트 배경

BUYMA 상품을 관리하면서 경쟁 상품 가격을 반복해서 확인하고, 조건에 맞는 상품의 판매가를 직접 수정하는 작업이 계속 발생했습니다. 상품 수가 늘어날수록 가격 확인과 변경 여부 판단에 시간이 들고, 한 번에 너무 큰 폭으로 가격을 조정하지 않도록 일관된 기준을 적용하는 것도 중요했습니다.

이 과정을 자동화하기 위해 Google Sheets를 상품 목록과 실행 결과의 기준으로 사용하고, 경쟁 가격 비교와 가격 변경 요청을 하나의 흐름으로 연결했습니다.

## 전체 처리 흐름

~~~text
Google Sheets 상품 URL
        │
        ▼
BUYMA 경쟁 상품 조회
        │
        ▼
BestShip 내 상품 및 현재 판매가 조회
        │
        ▼
가격 정책 계산
  ├── 이미 경쟁 최저가 이하인가?
  ├── 목표 가격이 유효한가?
  └── 인하 금액이 허용 범위인가?
        │
        ▼
미리보기 및 변경 대상 확인
        │
        ▼
BUYMA Product API 변경 요청
        │
        ▼
Google Sheets / CSV 실행 이력
~~~

## 가격 정책

<TechStack items={["Python", "uv", "Playwright", "Google Sheets API", "BUYMA Product API", "pytest"]} />

가격 계산은 pricing.py의 순수 함수로 분리했습니다. 경쟁 최저가를 무조건 따라가는 방식이 아니라, 현재 가격과 설정된 제한값을 함께 확인해 변경 여부를 결정합니다.

~~~python
target_price = competitor_min - delta
reduction = current_price - target_price

# current_price > competitor_min
# target_price > 0
# reduction <= max_change
~~~

delta는 경쟁 최저가보다 낮게 설정할 금액이고, max_change는 한 번 실행할 때 허용할 최대 인하 금액입니다. 두 기준은 config.yaml에서 관리합니다.

## 안정성과 검증

<CalloutBox type="warning">
  자동 테스트는 모의 HTTP 응답과 Google Sheets 객체를 사용합니다. 테스트가 통과해도 실제 BUYMA 계정의 가격 변경 성공까지 보장하지는 않습니다. 운영 환경에서는 인증 정보, API 권한, 상품 상태와 외부 서비스 응답을 별도로 확인해야 합니다.
</CalloutBox>

타임세일 상품은 설정에 따라 변경 대상에서 제외할 수 있도록 했습니다. 예약 실행 중 추가 인증이나 외부 서비스 문제가 발생하면 해당 실행을 무리하게 진행하지 않도록 처리하고, 결과와 사유를 기록하는 흐름을 두었습니다.

## AI 도구 활용과 개발 기여

AI 도구는 가격 변경 규칙을 정리하고 예외 조건을 검토하거나, API 연동 코드와 테스트 시나리오를 구체화하는 데 활용했습니다. 다만 가격 정책의 기준값과 실제 운영 방식은 직접 결정했습니다. 특히 이미 최저가인 상품, 0 이하 가격, 허용 한도 초과, 타임세일 상품 등 변경하면 안 되는 상황을 코드와 테스트로 분리해 검증했습니다.

## 정리

이 프로젝트에서 중요한 것은 가격을 자동으로 바꾸는 기능 자체보다, **어떤 상황에서 변경하고 어떤 상황에서는 변경하지 않을지**를 명확하게 정의하는 것이었습니다. 반복 업무를 줄이면서도 외부 시스템에 영향을 주는 자동화에는 미리보기, 제한 조건, 실행 기록과 테스트가 함께 필요하다는 점을 경험했습니다.
