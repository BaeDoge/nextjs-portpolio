## 프로젝트 배경

업무를 하면서 알게 된 설정 방법이나 장애 해결 과정은 메신저, 개인 문서, 브라우저 즐겨찾기 등 여러 곳에 흩어지기 쉽습니다. 같은 문제를 다시 만났을 때 예전에 정리한 내용을 찾지 못해 처음부터 조사하는 경우도 생깁니다.

이런 정보를 제목과 본문만으로 쌓아두는 것이 아니라 카테고리와 태그로 분류하고, 관련 파일까지 함께 저장한 뒤 필요한 키워드로 빠르게 검색할 수 있도록 지식 저장소를 만들었습니다.

## 검색 구조

SQLite FTS5를 이용해 제목, 본문, 태그를 전문 검색 대상으로 구성했습니다. 지식 데이터가 등록·수정·삭제될 때 검색 인덱스가 함께 갱신되도록 트리거를 사용합니다.

## 설계에서 고려한 점

### 별도 인프라 없이 실행 가능한 구조

개인 또는 소규모 내부 환경에서 사용하기 때문에 DB 서버를 별도로 운영하지 않는 구성을 선택했습니다. SQLite WAL 모드와 외래 키를 설정하고, 데이터베이스와 첨부파일을 함께 백업할 수 있도록 했습니다.

### 저장보다 검색을 우선한 정보 구조

정보를 많이 기록해도 필요한 순간에 찾지 못하면 실제 업무에서 활용하기 어렵습니다. 카테고리와 태그를 보조 분류로 사용하고, 키워드 검색을 주요 탐색 방식으로 두었습니다.

<CalloutBox type="warning">
  현재 구현은 경량 셀프 호스팅 도구로, 다중 사용자 인증이나 조직 단위 권한 관리를 제공하지 않습니다. 업무 자료를 저장한다면 localhost 또는 신뢰할 수 있는 내부 네트워크에서 실행하고 데이터 디렉터리와 백업 파일 접근 권한을 별도로 관리해야 합니다.
</CalloutBox>

## AI 도구 활용과 개발 기여

어떤 정보를 저장할지보다 시간이 지난 뒤에도 다시 찾기 쉬운 구조를 만드는 것을 우선으로 두었습니다. 지식 항목의 데이터 모델, 카테고리 관리, FTS5 검색 흐름, 첨부파일 연결 방식을 직접 정하고 기능을 구현했습니다.

AI 도구는 데이터 모델과 검색 흐름을 검토하고, API와 CLI의 반복적인 코드를 작성하거나 오류를 분석하는 데 활용했습니다. 다만 검색 결과가 실제 사용 목적에 맞는지, 데이터와 첨부파일이 일관되게 관리되는지 직접 확인하며 수정했습니다.

## 정리

Knowledge Vault는 경험을 단순히 저장하는 메모장이 아니라, 반복되는 업무 지식을 구조화하고 필요할 때 다시 찾기 위한 작은 플랫폼입니다. 검색 인덱스와 첨부파일, API와 CLI를 함께 설계하면서 업무 지식의 재사용성을 높이는 방법을 고민했습니다.
