## 프로젝트 배경

사내 밴드 공연을 준비하면서 가장 먼저 필요했던 것은 공연 정보를 관객에게 쉽고 정확하게 전달할 수 있는 페이지였습니다. 일정과 장소, 멤버, 셋리스트를 한곳에 정리하는 것에서 출발했지만, 공연을 기다리는 과정 자체도 하나의 경험이 될 수 있다고 생각했습니다.

그래서 단순한 초대장 대신 관객이 응원 메시지를 남기고, 궁금한 점을 질문하고, 뒤풀이 참석 여부를 전달할 수 있는 기능을 함께 설계했습니다. 운영자는 별도의 화면에서 참여 현황과 질문을 확인할 수 있도록 했습니다.

운영 페이지: [BAND NIGHT](https://daeil-band.vercel.app)

<CalloutBox type="info">
  이 프로젝트는 사내 밴드 공연을 위한 실제 행사 페이지로 기획하고 배포했습니다. 모바일 QR 접속을 기본 사용 시나리오로 두고, 관객이 별도 앱을 설치하거나 계정을 만드는 과정 없이 참여할 수 있도록 구성했습니다.
</CalloutBox>

## 사용자 흐름

1. **공연 정보 확인** — QR 코드 또는 공유 링크로 접속해 일정, 장소, 멤버와 셋리스트를 확인합니다.
2. **관객 참여** — 닉네임을 등록하고 이모티콘 응원, 질문, 뒤풀이 참석 응답을 남깁니다.
3. **운영자 확인** — 운영자는 별도 관리 화면에서 응원 수, 질문, 방문 현황과 참석 응답을 확인하고 필요한 관리를 진행합니다.
4. **공연 이후 기록** — 행사가 끝난 뒤에는 참여 기능을 정리하고 사진 아카이브를 중심으로 페이지를 유지합니다.

## 설계에서 중요하게 본 부분

### 참여 기능과 행사 이후 페이지의 분리

공연 전에는 응원과 질문, 참석 응답이 필요하지만 행사가 끝난 이후에는 이 기능들이 더 이상 필요하지 않습니다. 그래서 행사 종료 시점에 따라 페이지의 동작을 바꾸고, 이후에는 정적 콘텐츠만으로도 페이지를 유지할 수 있도록 했습니다.

### 데이터 요청과 운영 부담

관객이 동시에 접속할 수 있는 행사 페이지 특성을 고려해 응원 집계를 데이터베이스 함수에서 계산하고, 공개 페이지에서는 단일 API로 결과를 가져오도록 개선했습니다. 운영자 화면에서만 필요한 상세 데이터와 공개 화면의 조회 데이터를 분리한 것도 같은 이유입니다.

### 사용자 식별의 범위

<CalloutBox type="warning">
  현재 관객 식별은 계정 로그인이 아니라 브라우저 UUID를 이용합니다. 다른 기기나 시크릿 모드에서는 같은 사람도 별도 사용자로 인식될 수 있으므로, 계정 단위 인증이나 강한 사용자 제재를 제공하는 시스템은 아닙니다.
</CalloutBox>

## AI 도구 활용과 개발 기여

요구사항을 기능 단위로 정리하고 화면 흐름과 데이터 구조를 설계한 뒤, ChatGPT를 포함한 AI 도구를 UI 대안 검토, API 흐름 정리, SQL 초안 작성과 오류 분석에 활용했습니다. 특히 사용자 관리, 참여 데이터 집계, 행사 종료 후 모드처럼 요구사항이 추가되기 쉬운 기능은 작은 단위로 나눠 구현하고 실제 배포 환경에서 동작을 확인했습니다.

AI가 생성한 코드를 그대로 붙이는 방식보다는, 제안된 구현을 검토하고 기존 구조에 맞게 수정한 다음 모바일 브라우저와 운영 화면에서 직접 확인하는 방식으로 진행했습니다. 기획, 기능 우선순위 결정, 구현 통합, 배포와 운영 개선은 직접 담당했습니다.

## 정리

작은 행사 안내 페이지도 실제 사용자가 참여하고 운영자가 데이터를 관리하기 시작하면 하나의 서비스에 가까운 설계가 필요하다는 점을 경험했습니다. 기능을 추가하는 것만큼이나 행사 종료 이후의 동작, 데이터 요청량, 운영 편의성과 사용자 식별의 한계를 함께 고려하는 것이 중요했습니다.
