## 프로젝트 개요

팀 일정과 업무 진행 상황이 메신저, 개인 캘린더, 파일 폴더에 흩어져 있으면 필요한 정보를 다시 찾거나 다른 구성원에게 공유하기 어렵습니다. 이 문제를 줄이기 위해 일정, Todo, 작업 관련 정보를 한곳에서 확인할 수 있는 사내 공용 캘린더를 만들었습니다.

## 주요 기능

- **캘린더:** 월간·주간 일정 조회와 일정 등록 및 수정
- **업무 구분:** SR, CM, 회의, 휴가 등 일정 유형과 환경·담당자·작업 번호 관리
- **Todo:** 개인 및 공용 Todo, 담당자, 마감일, 우선순위와 진행 상태 관리
- **협업:** 일정별 댓글과 산출물 및 계획서 첨부
- **관리:** 사용자와 일정 관리, 삭제된 항목 이력 확인 및 복구
- **탐색:** 일정과 Todo 검색, 목록 페이지네이션 및 Kanban 형태의 업무 확인

## 구현

FastAPI와 SQLite를 사용해 사내망에서 실행할 수 있는 단일 웹 애플리케이션으로 구성했습니다. 데이터베이스는 WAL 모드와 외래 키를 사용하며, 일정·Todo·첨부파일·댓글·활동 이력을 분리해 관리합니다.

| 영역 | 구성 |
| --- | --- |
| Backend | Python, FastAPI |
| Database | SQLite |
| Template / UI | Jinja2, HTML, CSS, JavaScript |
| Runtime | uv, Uvicorn |

## 개발 과정

실제 팀에서 일정과 산출물을 관리하는 흐름을 기준으로 데이터 구조와 화면을 설계했습니다. 초기 기능을 만든 뒤 구성원이 사용하는 과정에서 나온 요청을 반영해 댓글, 파일 첨부, Kanban, 관리자 이력과 검색 기능을 단계적으로 추가했습니다.

AI 도구는 요구사항을 기능 단위로 나누고, 데이터 모델과 화면 흐름을 검토하며, 반복적인 구현과 오류 분석을 빠르게 진행하는 데 활용했습니다. 실제 업무 방식에 맞는 기준을 정하고 기능을 통합·수정하는 과정은 직접 수행했습니다.

## 운영 및 보안 고려사항

현재 사용자 구분은 계정 기반 인증 대신 브라우저 식별자와 접속 IP 정보를 활용합니다. 따라서 조직의 SSO나 계정 단위 권한 관리가 필요한 서비스와는 다르며, 공개 인터넷에 그대로 배포하기보다는 신뢰할 수 있는 내부 네트워크에서 사용하는 것을 전제로 합니다. 실제 조직에 도입할 때는 인증, 접근 제어, 백업 및 데이터 보존 정책을 별도로 검토해야 합니다.
