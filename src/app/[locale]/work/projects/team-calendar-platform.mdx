## 프로젝트 배경

팀의 일정과 업무 진행 상황이 메신저 대화, 개인 캘린더, 엑셀과 파일 폴더에 나뉘어 있으면 필요한 정보를 다시 찾기 어렵고, 담당자별 진행 상태를 한눈에 파악하기도 쉽지 않습니다.

이런 불편을 줄이기 위해 일정과 Todo를 하나의 캘린더에서 관리하고, 작업과 관련된 계획서나 산출물도 일정에 연결할 수 있는 내부 웹 도구를 만들었습니다. 기능을 크게 확장하기보다 실제 팀에서 반복적으로 사용하는 정보와 동선을 한 화면에서 확인하도록 하는 데 초점을 두었습니다.

## 데이터 구조와 요청 흐름

~~~text
사용자 브라우저
      │
      ▼
FastAPI
      │
      ├── Calendar Events
      ├── Todo Items
      ├── Comments
      ├── Attachments
      └── User / Activity History
      │
      ▼
SQLite
  ├── users
  ├── events
  ├── todos
  ├── attachments
  ├── event_comments
  └── activity_logs
~~~

일정과 Todo를 분리하고, 댓글과 첨부파일을 별도 테이블로 관리해 각 기능이 서로의 데이터 구조에 과도하게 종속되지 않도록 구성했습니다. SQLite의 외래 키와 WAL 모드를 사용하고, 삭제된 데이터와 활동 이력을 확인할 수 있는 관리 기능도 추가했습니다.

## 운영 환경과 보안 범위

<CalloutBox type="warning">
  이 프로젝트는 부서 내부망에서 사용하는 경량 협업 도구입니다. 현재 사용자 구분은 브라우저 식별자와 접속 IP 정보를 활용하며, 조직 SSO나 계정 기반 권한 관리 수준을 제공하지 않습니다. 외부 인터넷에 공개하려면 인증·인가, HTTPS, 접근 제어와 백업 정책을 별도로 보강해야 합니다.
</CalloutBox>

업무 자료를 다루는 특성상 기능을 추가하는 것뿐 아니라 실행 서버에 대한 접근 권한과 데이터 디렉터리의 백업도 함께 고려해야 합니다. 실제 조직 공용 서비스로 확대할 경우에는 사용자 인증과 역할별 권한 체계를 먼저 정비해야 합니다.

## AI 도구 활용과 개발 기여

실제 팀의 일정 관리 방식과 산출물 공유 흐름을 기준으로 요구사항을 정의하고, 데이터 모델과 화면 구성을 직접 설계했습니다. 이후 사용하면서 나온 요청을 기능 단위로 나눠 댓글, 첨부파일, Kanban, 관리자 이력과 검색 기능을 추가했습니다.

AI 도구는 요구사항을 구체적인 작업으로 분해하고, 데이터 구조와 화면 흐름을 검토하며 반복적인 코드 작성과 오류 분석을 보조하는 데 활용했습니다. 제안된 구현이 기존 데이터와 운영 방식에 맞는지 확인하고, 통합과 수정 및 최종 동작 검증을 직접 진행했습니다.

## 정리

이 프로젝트를 통해 팀에서 사용하는 작은 업무 도구도 일정, 사용자, 첨부파일, 변경 이력처럼 서로 연결된 데이터 모델을 필요로 한다는 점을 경험했습니다. 실제 사용 흐름을 관찰하고 기능을 단계적으로 보강하는 과정에서 내부 업무 도구를 설계하고 운영하는 감각을 익힐 수 있었습니다.
