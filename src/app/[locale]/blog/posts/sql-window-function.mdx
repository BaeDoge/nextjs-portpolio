## 예전에 쓰던 방식

"사용자별 최근 대화 1건씩"을 가져오는 쿼리를 이렇게 짰습니다.

```sql
SELECT c.*
FROM chat_logs c
INNER JOIN (
  SELECT user_id, MAX(created_at) AS max_created
  FROM chat_logs
  GROUP BY user_id
) latest
  ON c.user_id = latest.user_id
 AND c.created_at = latest.max_created;
```

동작은 합니다. 그런데 같은 시각에 두 건이 있으면 중복이 나옵니다.
그걸 막으려고 조건을 더 붙이다 보면 길어집니다.

## 윈도우 함수로

```sql
SELECT *
FROM (
  SELECT c.*,
         ROW_NUMBER() OVER (
           PARTITION BY user_id
           ORDER BY created_at DESC, id DESC
         ) AS rn
  FROM chat_logs c
) t
WHERE rn = 1;
```

`ORDER BY`에 `id DESC`를 같이 넣어서 동점 상황도 결정적으로 처리됩니다.

## 자주 쓰게 된 것들

**직전 값과 비교 — LAG**

```sql
SELECT
  measured_at,
  value,
  value - LAG(value) OVER (ORDER BY measured_at) AS diff
FROM metrics;
```

일별 증감을 구할 때 자기 자신을 조인할 필요가 없어집니다.

**누적 합 — SUM OVER**

```sql
SELECT
  dt,
  amount,
  SUM(amount) OVER (ORDER BY dt) AS running_total
FROM daily_sales;
```

**그룹 내 순위 — RANK / DENSE_RANK**

```sql
SELECT
  category,
  name,
  RANK() OVER (PARTITION BY category ORDER BY score DESC) AS rnk
FROM items;
```

`RANK`는 동점 뒤 순위를 건너뛰고(1,1,3), `DENSE_RANK`는 안 건너뜁니다(1,1,2).
헷갈려서 매번 확인합니다.

## 주의할 점

윈도우 함수는 `WHERE`에서 바로 못 씁니다.

```sql
-- 안 됨
WHERE ROW_NUMBER() OVER (...) = 1

-- 서브쿼리로 감싸야 함
```

`WHERE`가 윈도우 함수보다 먼저 평가되기 때문입니다.
이건 몇 번 당하고 나서야 몸에 익었습니다.
