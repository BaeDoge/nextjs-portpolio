오늘은 윈도우 함수를 활용해 쿼리를 개선한 사례를 정리해 보겠습니다.

## 기존 방식

사용자별 최근 데이터 1건을 조회하는 쿼리를 서브쿼리로 작성했습니다.

```sql
SELECT c.*
FROM chat_logs c
INNER JOIN (
  SELECT user_id, MAX(created_at) AS max_created
  FROM chat_logs
  GROUP BY user_id
) latest
  ON c.user_id = latest.user_id
 AND c.created_at = latest.max_created;
```

동일 시각에 여러 건이 존재하는 경우 중복이 발생하는 문제가 있었습니다.

## 개선

```sql
SELECT *
FROM (
  SELECT c.*,
         ROW_NUMBER() OVER (
           PARTITION BY user_id
           ORDER BY created_at DESC, id DESC
         ) AS rn
  FROM chat_logs c
) t
WHERE rn = 1;
```

`ORDER BY`에 `id DESC`를 추가해 동점 상황에서도 결과가 일정하게 유지되도록 했습니다.

## 활용 사례

**LAG — 이전 행과 비교**

```sql
SELECT
  measured_at,
  value,
  value - LAG(value) OVER (ORDER BY measured_at) AS diff
FROM metrics;
```

**SUM OVER — 누적 합계**

```sql
SELECT
  dt,
  amount,
  SUM(amount) OVER (ORDER BY dt) AS running_total
FROM daily_sales;
```

**RANK / DENSE_RANK — 그룹 내 순위**

```sql
SELECT
  category,
  name,
  RANK() OVER (PARTITION BY category ORDER BY score DESC) AS rnk
FROM items;
```

## 참고 사항

윈도우 함수는 `WHERE` 절에서 직접 사용할 수 없으며, 서브쿼리로 감싸야 합니다. `WHERE`가 윈도우 함수보다 먼저 평가되기 때문입니다.

## 결론

MySQL 8.0부터 지원되는 기능으로, 서브쿼리 기반 쿼리를 대체하는 데 효과적이었습니다. DB 버전 업그레이드 시 신규 지원 기능을 확인하는 절차가 필요하다고 판단했습니다.
