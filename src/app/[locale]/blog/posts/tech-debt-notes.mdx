오늘은 기술 부채를 기록하는 방식을 개선한 과정을 정리해 보겠습니다.

## 문제

```python
# TODO: 나중에 캐싱 추가
# FIXME: 임시 처리
```

이러한 주석을 다수 남겼으나, 시간이 지난 후 확인해보니 배경 정보가 남아있지 않아 처리 여부를 판단하기 어려웠습니다.

## 시도 1 — 이슈로 전환

전체 항목을 GitHub 이슈로 전환했으나, 우선순위가 없어 신규 기능 개발에 밀려 처리되지 않는 문제가 있었습니다.

## 시도 2 — 주석에 맥락 추가

```python
# [부채] 2025-11-20 / 배승호
# 상황: 일정상 동기 호출로 처리
# 영향: 요청 증가 시 타임아웃 가능. 현재 일 300건 수준
# 조건: 일 1000건 초과 시 큐 구조로 전환 필요
```

처리 조건을 명시함으로써 판단 기준을 코드 내에 남길 수 있었습니다.

## 시도 3 — 별도 문서로 관리

```markdown
| 항목 | 조건 | 영향 | 기록일 |
|---|---|---|---|
| 동기 파일 처리 | 일 1000건 초과 시 | 타임아웃 | 2025-11-20 |
| 하드코딩된 카테고리 | 카테고리 추가 요청 시 | 배포 필요 | 2025-10-02 |
```

분기 단위로 검토하며, 조건이 충족된 항목을 우선 처리 대상으로 선정하고 있습니다.

## 결론

기술 부채는 완전히 제거하기보다 관리 대상으로 접근하는 것이 현실적이라고 판단했습니다. 처리 조건을 명시하는 것이 판단 근거를 남기는 데 효과적이었습니다.
