## TODO 주석의 한계

```python
# TODO: 나중에 캐싱 추가
# FIXME: 이 로직 임시방편임
```

이런 걸 꽤 남겼는데, 몇 달 뒤 grep 해보니 30개가 넘었고
대부분 배경을 기억 못 했습니다.

`git blame`으로 시점은 알 수 있지만 "왜 임시로 뒀는지"는 안 나옵니다.

## 시도 1 — 이슈로 전환

전부 GitHub 이슈로 옮겼습니다.
결과는, 이슈가 쌓이기만 하고 처리는 안 됐습니다.

우선순위가 없으니 항상 새 기능에 밀립니다. 예상한 결과였습니다.

## 시도 2 — 주석에 맥락을 적기

형식을 정했습니다.

```python
# [부채] 2025-11-20 / 배승호
# 상황: 마감 때문에 동기 호출로 처리함
# 문제: 요청 수가 늘면 타임아웃 가능성. 현재 일 300건이라 버팀
# 조건: 일 1000건 넘으면 큐로 전환 필요
```

**"조건"을 적는 게 핵심이었습니다.**
"나중에"가 아니라 "이 숫자가 되면"이라고 적으니
판단 기준이 코드 안에 남습니다.

## 시도 3 — 부채 목록을 문서로

레포에 `DEBT.md`를 두고 주기적으로 훑습니다.

```markdown
| 항목 | 조건 | 영향 | 기록일 |
|---|---|---|---|
| 동기 파일 처리 | 일 1000건 초과 시 | 타임아웃 | 2025-11-20 |
| 하드코딩된 카테고리 | 카테고리 추가 요청 시 | 배포 필요 | 2025-10-02 |
```

분기에 한 번 이 표를 봅니다.
조건이 충족된 항목만 처리 대상으로 올립니다.

## 지금 상태

완벽하진 않습니다. 표를 업데이트하는 걸 자꾸 잊습니다.
다만 "언제 손봐야 하는지"가 적혀 있으니
적어도 "이걸 왜 이렇게 뒀지"로 시간 쓰는 일은 줄었습니다.

## 생각

기술 부채는 없앨 수 없고 관리하는 대상이라는 말에 동의하게 됐습니다.
중요한 건 갚는 게 아니라 **언제 갚아야 하는지 아는 것**인 것 같습니다.
