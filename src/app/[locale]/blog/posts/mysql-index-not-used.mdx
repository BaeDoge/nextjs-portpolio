오늘은 인덱스가 있음에도 조회 성능이 개선되지 않았던 사례를 정리해 보겠습니다.

## 상황

조회 API의 응답 시간이 3초 이상으로 느려졌습니다. 해당 컬럼에는 인덱스가 생성되어 있는 상태였습니다.

## 원인 확인

```sql
EXPLAIN SELECT * FROM chat_logs
WHERE DATE(created_at) = '2026-03-20';
```

```
type: ALL
key: NULL
rows: 2841203
```

`key` 값이 NULL로, 인덱스가 사용되지 않고 있었습니다. `DATE(created_at)`처럼 인덱스 컬럼에 함수를 적용하면 MySQL은 인덱스를 사용할 수 없습니다.

## 해결

조건을 범위 검색으로 변경했습니다.

```sql
SELECT * FROM chat_logs
WHERE created_at >= '2026-03-20 00:00:00'
  AND created_at <  '2026-03-21 00:00:00';
```

```
type: range
key: idx_created_at
rows: 4210
```

응답 시간이 3초에서 40ms로 개선되었습니다.

## 유사 패턴

아래와 같은 조건도 동일하게 인덱스를 타지 않습니다.

```sql
WHERE YEAR(created_at) = 2026
WHERE CAST(user_id AS CHAR) = '123'
WHERE user_id + 0 = 123
```

## 결론

인덱스 컬럼에 함수나 형변환을 적용하면 인덱스가 무효화됩니다. 이후로는 쿼리가 느려질 경우 `EXPLAIN`으로 `key`와 `rows` 값을 우선 확인하는 절차를 거치고 있습니다.
