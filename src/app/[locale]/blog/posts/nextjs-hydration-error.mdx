## 증상

```
Hydration failed because the server rendered HTML didn't match the client.
```

화면은 정상인데 콘솔에만 에러가 뜹니다. 무시하고 싶은 종류의 에러인데,
무시하면 나중에 실제 렌더링이 깨집니다.

## 원인 찾기

에러 메시지가 어떤 노드에서 어긋났는지는 알려줍니다.
따라가 보니 게시글 목록의 날짜 부분이었습니다.

```tsx
<span>{new Date(post.publishedAt).toLocaleDateString()}</span>
```

`toLocaleDateString()`은 **실행 환경의 로케일**을 따릅니다.
서버(Node, UTC/en-US)와 브라우저(KST/ko-KR)가 서로 다른 문자열을 만듭니다.

- 서버: `3/21/2026`
- 브라우저: `2026. 3. 21.`

HTML이 다르니 hydration이 깨집니다.

## 해결

로케일과 타임존을 명시했습니다.

```tsx
function formatDate(iso: string) {
  return new Intl.DateTimeFormat("ko-KR", {
    timeZone: "Asia/Seoul",
    year: "numeric",
    month: "long",
    day: "numeric",
  }).format(new Date(iso));
}
```

서버든 브라우저든 같은 결과가 나옵니다.

## 같은 부류의 함정들

hydration 에러는 대부분 "서버와 브라우저에서 값이 달라지는 것"이 원인입니다.

```tsx
// 위험
{Math.random()}
{new Date().toLocaleString()}
{typeof window !== "undefined" ? "A" : "B"}
{localStorage.getItem("theme")}
```

정말 브라우저에서만 결정돼야 하는 값이면, 마운트 후에 넣습니다.

```tsx
const [mounted, setMounted] = useState(false);
useEffect(() => setMounted(true), []);

if (!mounted) return null;
return <ThemeAwareThing />;
```

이 방식은 첫 프레임에 아무것도 안 그려지니 레이아웃이 흔들릴 수 있습니다.
높이를 미리 잡아두면 덜 티납니다.

## 정리

"서버와 클라이언트가 같은 HTML을 그리는가"만 계속 물으면 대부분 잡힙니다.
날짜, 랜덤, 브라우저 전용 API. 이 셋이 단골입니다.
