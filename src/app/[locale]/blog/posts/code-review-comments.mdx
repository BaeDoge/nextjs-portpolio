## 계기

제가 남긴 리뷰가 반영이 잘 안 됐습니다.
처음엔 상대 문제인 줄 알았는데, 제 코멘트를 모아 놓고 보니 이유가 보였습니다.

```
이거 N+1 나올 것 같은데요
```

틀린 말은 아닙니다. 그런데 받는 사람 입장에서는
"어디가? 왜? 어떻게 고치라고?"가 전부 빠져 있습니다.

## 바꾼 형식

세 가지를 붙이기로 했습니다.

**1. 무엇이 문제인지 구체적으로**

```
이 반복문 안의 user.profile 접근이 매 회차마다 쿼리를 날립니다.
목록이 100개면 쿼리가 101번 나갑니다.
```

**2. 왜 문제인지**

```
지금은 목록이 짧아서 티가 안 나는데,
관리자 화면에서 500건까지 조회할 수 있어서 거기서 터질 겁니다.
```

**3. 어떻게 하면 되는지 (또는 모르겠으면 모른다고)**

```
select_related("profile")를 붙이면 한 번에 가져옵니다.
```

## 라벨을 붙였다

모든 코멘트가 "반드시 고쳐야 함"은 아닙니다. 그래서 앞에 표시를 답니다.

- `[must]` 머지 전에 고쳐야 함
- `[nit]` 취향 문제, 무시해도 됨
- `[question]` 비판 아니고 진짜 궁금함

`[nit]`을 붙이기 시작한 뒤로 사소한 지적에 대한 스트레스가 줄었습니다.
받는 쪽도 "이건 넘어가도 되는구나"를 바로 알 수 있습니다.

`[question]`도 의외로 유용했습니다.
제가 모르는 맥락이 있었던 경우가 생각보다 많았습니다.

## 남은 고민

여전히 어려운 건 "구조를 다시 짜야 할 것 같은데"를 전달하는 일입니다.
PR 코멘트로 하기엔 너무 크고, 그냥 넘기기엔 찜찜한 경우.

요즘은 그럴 때 코멘트 대신 직접 얘기하러 갑니다.
글로 쓰면 길어지기만 하고 서로 방어적이 되더군요.
