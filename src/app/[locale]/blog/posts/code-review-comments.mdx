오늘은 코드 리뷰 코멘트 작성 방식을 개선한 내용을 정리해 보겠습니다.

## 문제

작성한 리뷰 코멘트가 실제 반영으로 잘 이어지지 않는 경우가 많았습니다. 기존 코멘트를 확인해보니 다음과 같은 형태였습니다.

```
이거 N+1 나올 것 같은데요
```

문제 지적은 맞았지만, 어느 부분이 왜 문제이고 어떻게 수정해야 하는지에 대한 정보가 부족했습니다.

## 개선한 형식

코멘트에 세 가지 요소를 포함하도록 변경했습니다.

**1. 문제 지점**

```
이 반복문 안의 user.profile 접근이 매 회차마다 쿼리를 발생시킵니다.
목록이 100개면 쿼리가 101번 실행됩니다.
```

**2. 발생 가능한 영향**

```
현재는 목록이 짧아 문제가 드러나지 않지만,
관리자 화면에서는 최대 500건까지 조회되어 지연이 발생할 수 있습니다.
```

**3. 수정 방향**

```
select_related("profile")를 적용하면 쿼리 1회로 처리됩니다.
```

## 라벨 적용

코멘트의 우선순위를 구분하기 위해 라벨을 추가했습니다.

- `[must]` — 머지 전 반드시 수정
- `[nit]` — 선택 사항
- `[question]` — 확인을 위한 질문

라벨을 적용한 이후 사소한 지적에 대한 불필요한 논쟁이 줄었습니다.

## 결론

리뷰 코멘트에 문제, 영향, 해결 방향을 함께 작성하는 것이 반영률을 높이는 데 효과적이었습니다. 구조적인 변경이 필요한 경우에는 코멘트보다 직접 논의하는 방식을 사용하고 있습니다.
