오늘은 RAG 시스템에 사용할 임베딩 모델을 선정한 과정을 정리해 보겠습니다.

## 상황

한국어 문서 위주에 일부 영어 기술 용어가 포함된 데이터로 RAG를 구성해야 했습니다.

## 문제

리더보드 상위 모델을 적용했으나, 실제 검색 결과의 품질이 기대에 미치지 못했습니다. 원인을 확인해보니 벤치마크 데이터셋(뉴스, 일반 문장)과 실제 데이터(약관 등 형식적인 장문)의 특성이 달랐습니다.

## 해결

자체 평가셋을 구성했습니다. 실제 사용자 질문 50건에 대해 정답 청크를 직접 라벨링하고, Recall@5 기준으로 모델을 비교했습니다.

확인된 사항은 다음과 같습니다.

**1. 다국어 모델이 영어 혼용 문서에서 유리했습니다.**

**2. 임베딩 차원과 성능이 비례하지 않았습니다.** 1024차원과 384차원 모델의 Recall@5 차이는 크지 않았고, 저장 용량과 지연 시간에서는 차이가 뚜렷했습니다.

**3. 정규화 처리가 누락되어 있었습니다.** 코사인 유사도를 사용하는 경우 임베딩 정규화가 필요합니다.

```python
output = model(text, pooling="mean", normalize=True)
```

## 결론

최종적으로 384차원 다국어 모델을 선정했습니다. 리더보드 순위는 낮았지만 실제 데이터에서는 더 적합했고, 연산 비용도 낮았습니다. 자체 평가셋을 구성하는 작업이 벤치마크 참고보다 실질적인 도움이 되었습니다.
