오늘은 GitHub 트렌딩을 6개월간 관찰하며 정리한 내용을 공유해 보겠습니다.

## 배경

새로운 도구를 뒤늦게 접하는 경우가 많아, 6개월간 주 1회 GitHub 트렌딩을 확인했습니다.

## 관찰 1 — 기존 라이브러리를 감싼 프로젝트가 많음

기존 라이브러리를 편의 기능으로 감싼 프로젝트가 다수였습니다. 도입 전 직접 구현 시 소요될 코드량을 먼저 확인하는 절차를 추가했습니다.

## 관찰 2 — 스타 수와 유지보수 여부는 별개

스타 수가 많지만 최근 커밋이 오래된 저장소가 다수 있었습니다. 현재는 다음 순서로 확인하고 있습니다.

1. 최근 커밋 일자
2. 이슈 처리 비율
3. 메인테이너 수
4. 스타 수

## 관찰 3 — README 구성과 실용성

배지와 비교 표가 많은 저장소일수록 핵심 목적이 불명확한 경우가 있었습니다. 문제, 해결, 설치, 예제로 구성된 짧은 README가 대체로 실용적이었습니다.

## 결론

6개월간 관찰한 프로젝트 중 실제로 업무에 도입한 것은 2건이었습니다. 도입률은 낮았지만, 트렌드를 지속적으로 확인하는 과정 자체가 기술 선택의 기준을 세우는 데 도움이 되었습니다.
