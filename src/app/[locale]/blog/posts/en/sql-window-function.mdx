Today I'll write up a case where I improved a query using window functions.

## The old approach

I had written a query to fetch each user's latest row using a subquery.

```sql
SELECT c.*
FROM chat_logs c
INNER JOIN (
  SELECT user_id, MAX(created_at) AS max_created
  FROM chat_logs
  GROUP BY user_id
) latest
  ON c.user_id = latest.user_id
 AND c.created_at = latest.max_created;
```

When several rows existed at the same timestamp, it produced duplicates.

## The improvement

```sql
SELECT *
FROM (
  SELECT c.*,
         ROW_NUMBER() OVER (
           PARTITION BY user_id
           ORDER BY created_at DESC, id DESC
         ) AS rn
  FROM chat_logs c
) t
WHERE rn = 1;
```

Adding `id DESC` to `ORDER BY` keeps the result consistent even when there are ties.

## Other uses

**LAG: compare with the previous row**

```sql
SELECT
  measured_at,
  value,
  value - LAG(value) OVER (ORDER BY measured_at) AS diff
FROM metrics;
```

**SUM OVER: running total**

```sql
SELECT
  dt,
  amount,
  SUM(amount) OVER (ORDER BY dt) AS running_total
FROM daily_sales;
```

**RANK / DENSE_RANK: rank within a group**

```sql
SELECT
  category,
  name,
  RANK() OVER (PARTITION BY category ORDER BY score DESC) AS rnk
FROM items;
```

## Note

Window functions can't be used directly in a `WHERE` clause and have to be wrapped in a subquery, because `WHERE` is evaluated before window functions.

## Conclusion

Supported since MySQL 8.0, window functions were effective in replacing subquery-based queries. I concluded that when upgrading a DB version, it is worth checking for newly supported features.
