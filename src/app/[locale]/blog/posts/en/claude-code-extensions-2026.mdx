Today I'll share what I sorted out after using Claude Code extensions for three months.

## Background

Many extensions that looked useful at install time were not ones I kept using, so I reviewed what I actually used.

## What I kept

**1. A project context file**

Recording project conventions in a file at the repo root reduced how often I had to repeat explanations.

```markdown
- This project uses Flask + MySQL, no ORM
- Logs use structured logging (JSON); no print()
- Tests use pytest; file names are test_*.py
```

**2. Terminal integration**

Being able to work without switching windows improved my efficiency.

## What I dropped

**Automatic commit message generation**

It only described the diff, so it was hard to tell why a change was made.

```
- Update user_service.py to add validation logic and modify error handling
```

**Real-time inline suggestions**

They often interrupted my flow, so I turned them off.

## Conclusion

When adopting a tool, I think you need a standard that separates "things I can't work without" from "things that make work a bit easier." If the latter pile up, the cost of managing them can exceed their benefit.
