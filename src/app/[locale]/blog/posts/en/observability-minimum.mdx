Today I'll write up how I cleaned up my monitoring dashboards.

## Situation

I had set up more than 20 dashboards covering CPU, memory, network, disk I/O, and more, but during real incidents I only looked at one of them.

## Metrics I actually used

**1. Error rate**: number of 5xx responses / total requests

**2. p95 latency**: averages don't reflect the delays some users experience, so I switched to p95 and p99.

**3. Throughput**: I look at the change from normal rather than the absolute value.

## Metrics I dropped

I dropped the CPU and memory graphs. When those metrics had a problem, it almost always showed up in the three metrics above first.

## Changing the alert criteria

I redefined alerts, which came in dozens per day, around "does this need immediate action?" Items that don't need action moved to a dashboard instead of an alert. After applying this, alerts dropped to one or two a day.

## Conclusion

Rather than setting up every metric in advance, it was more efficient to first define the metrics I actually check and add more as needed.
