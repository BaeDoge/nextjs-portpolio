Today I'll write up how I improved a streaming response UI.

## Background

I built a UI that displays LLM responses as a stream. The basic feature worked, but a few problems showed up in use.

## Problem 1: Auto-scroll

The view scrolled to the bottom automatically while a response was being generated, so it jumped even when the user was reading earlier content.

**Fix**: I applied auto-scroll only when the user is near the bottom.

```ts
function isNearBottom(el: HTMLElement, threshold = 80) {
  return el.scrollHeight - el.scrollTop - el.clientHeight < threshold;
}
```

## Problem 2: Markdown rendering errors

During streaming, incomplete Markdown syntax was rendered and caused display errors.

**Fix**: If a code block was not closed during streaming, I closed it temporarily.

```ts
function safeMarkdown(text: string) {
  const fences = (text.match(/```/g) || []).length;
  return fences % 2 === 1 ? text + "\n```" : text;
}
```

## Problem 3: No way to stop a response

There was no way to stop a response while it was being generated.

**Fix**: I applied `AbortController`.

```ts
const controller = new AbortController();

fetch("/api/chat", {
  method: "POST",
  body: JSON.stringify({ messages }),
  signal: controller.signal,
});
```

## Problem 4: Unclear state when the connection closes

When the connection dropped mid-stream, it was hard to tell whether it had ended normally or with an error. I made the server send an explicit end signal, and the UI now shows an error state when that signal is missing.

## Conclusion

Beyond printing text, a streaming UI also has to handle scrolling, rendering, cancellation, and errors.
