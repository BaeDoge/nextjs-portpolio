Today I'll share the criteria I settled on after using Tailwind and CSS Modules together.

## Background

I ended up using both approaches in my portfolio project, so I sorted out which situations suit each one.

## When Tailwind fits

**Simple layouts**

```tsx
<div className="flex items-center gap-2 px-4 py-2 rounded-lg">
```

**Responsive handling**

```tsx
<div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3">
```

I could handle this without writing separate media queries.

## When CSS Modules fit

**Components with many states**

When hover, focus, disabled, and other states combine, the class strings got long and hard to read.

```css
.button:disabled {
  background: var(--gray-200);
  cursor: not-allowed;
}
```

**Animations**

Styles that include keyframes were more efficient to keep in a CSS file.

## The criteria I apply

- Layout, spacing, alignment → Tailwind
- Component-specific styles, state changes, animations → CSS Modules
- Color values shared through CSS variables

Without shared color values, dark mode ended up with mismatched values, so I made both sides reference common variables like this.

```css
:root {
  --surface: #ffffff;
}
@media (prefers-color-scheme: dark) {
  :root { --surface: #121212; }
}
```

## Conclusion

Rather than choosing one of the two, clearly separating where each applies was more efficient for maintenance.
