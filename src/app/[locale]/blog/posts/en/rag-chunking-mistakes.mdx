Today I'll write up how I improved the chunking strategy of a RAG system.

## Situation

I set up chunking with the common defaults, `chunk_size=512, overlap=50`. Applying it to clause-based documents such as terms and conditions caused problems.

## Problem

Splitting at 512 tokens sometimes cut between the paragraphs of a clause (①②③). In those cases, only the part saying "cancellation is possible" was retrieved, and the part with the "except for the following restrictions" was missing.

## How I improved it

**Attempt 1: Larger overlap**

I raised it to `overlap=200`, but similar chunks started being retrieved in duplicate.

**Attempt 2: Split by article**

```python
import re

def split_by_article(text: str) -> list[str]:
    parts = re.split(r'(제\s*\d+\s*조)', text)
    chunks = []
    for i in range(1, len(parts), 2):
        chunks.append(parts[i] + parts[i + 1])
    return chunks
```

The meaning units were preserved, but article lengths varied widely, so the embedding quality of long articles dropped.

**Final: Two-step splitting with the parent heading included**

1. Split by article first
2. Re-split long articles by paragraph
3. Include the parent article heading in each chunk

```
[Article 15 (Termination)] ② Notwithstanding paragraph 1, in each of the following cases...
```

## Conclusion

Setting the chunking boundary by the document's units of meaning rather than by token count was what improved retrieval accuracy. The right chunking criteria can differ by document type.
