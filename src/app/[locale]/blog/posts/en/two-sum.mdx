## Problem

Given an integer array `nums` and an integer `target`, return the indices of two numbers whose sum equals `target`. Each input has exactly one solution, and you cannot use the same element twice. The indices can be returned in any order.

For example, when `nums = [2, 7, 11, 15]` and `target = 9`, return `[0, 1]` because `nums[0] + nums[1] == 9`. The array contains between 2 and `10^4` elements, and the values and target are between `-10^9` and `10^9`.

## Approach

A brute-force solution uses two nested loops to check every pair. It works, but takes `O(n^2)) time. To improve the runtime, use a **hash map** while traversing the array. For each current number `num`, calculate its complement, `target - num`, and check whether that complement has already been seen. Store each visited number and its index in the map. If the complement exists, the answer is found immediately.

Each element is processed once, and hash-map lookups take average `O(1)) time, so the overall time complexity is `O(n)). The map requires up to `O(n)) extra space.

## Solution

The following Python implementation stores each number's index and checks for its complement before adding the current number to the map.

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        num_map = {}
        
        for i, num in enumerate(nums):
            complement = target - num
            
            if complement in num_map:
                return [num_map[complement], i]
            
            num_map[num] = i
            
        return []
```

The time complexity is `O(n)), because the array is traversed once. The worst-case space complexity is `O(n)), because every element may be stored in the hash map.

## Alternative Approaches

A brute-force solution checks every pair of indices `i` and `j`:

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                if nums[i] + nums[j] == target:
                    return [i, j]
        return []
```

This approach uses `O(1)) extra space, but takes `O(n^2)) time. With up to `10^4` elements, that can mean as many as `10^8` pair checks, which may time out. The hash-map approach is therefore more efficient.

## Additional Notes

The hash-map solution also works with negative numbers and duplicate values. Since the problem guarantees exactly one solution, the function can return as soon as the matching complement is found.

If the array is already sorted, a **two-pointer** approach is another option: move the left pointer right when the sum is too small, and move the right pointer left when it is too large. However, because the original indices are required, sorting an unsorted input would require additional bookkeeping.
