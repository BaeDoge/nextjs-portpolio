Today I'll write up a problem caused by duplicated validation logic.

## Problem

The phone number format validation was implemented separately in the frontend, the API, and the batch job. When the rule changed, I updated and deployed only the API, and data entered through the batch job ended up filtered out on lookup.

## Cause

Each area implemented its own validation, so the rule was being maintained in several places.

## Fix

I consolidated the validation logic into a single place.

```python
from pydantic import BaseModel, field_validator
import re

PHONE_RE = re.compile(r"^01[016789]-?\d{3,4}-?\d{4}$")

class Contact(BaseModel):
    phone: str

    @field_validator("phone")
    @classmethod
    def check_phone(cls, v: str) -> str:
        normalized = v.replace("-", "")
        if not PHONE_RE.match(v):
            raise ValueError("Invalid phone number format")
        return normalized
```

I changed the API and the batch job to reference the same model. The frontend needed a separate implementation because of the language, but I managed the regular expression as a shared constant.

## Side benefit

Applying normalization together with validation made the data format stored in the DB consistent.

## Conclusion

It is safer to manage validation rules in a single place and call them wherever needed. Handling validation and normalization together also helped keep data consistent.
