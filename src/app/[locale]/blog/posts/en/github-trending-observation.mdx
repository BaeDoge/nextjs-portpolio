Today I'll share what I sorted out after watching GitHub Trending for six months.

## Background

I often came across new tools late, so I checked GitHub Trending once a week for six months.

## Observation 1: Many projects just wrap existing libraries

Many projects wrapped an existing library with convenience features. Before adopting one, I added a step of checking how much code it would take to implement the same thing myself.

## Observation 2: Stars and maintenance are separate things

Many repositories had lots of stars but old recent commits. I now check things in this order:

1. Date of the latest commit
2. Issue resolution rate
3. Number of maintainers
4. Number of stars

## Observation 3: README structure and usefulness

In repositories with many badges and comparison tables, the core purpose was sometimes unclear. A short README made up of the problem, the solution, installation, and examples was usually the more practical one.

## Conclusion

Of the projects I watched over six months, two were actually adopted at work. The adoption rate was low, but the habit of following trends helped me build criteria for choosing technology.
