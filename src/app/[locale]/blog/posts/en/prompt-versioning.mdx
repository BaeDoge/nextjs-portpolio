Today I'll write up how I introduced version control for prompts.

## Problem

A drop in chatbot answer quality was reported. There were no code deployments or model changes. On checking, the prompt had been edited in the admin screen, and the previous version had not been saved anywhere.

Prompts directly affect behavior, yet their change history was not being managed.

## Fix

**1. Store prompts in the DB by version**

```sql
CREATE TABLE prompts (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  name        VARCHAR(100) NOT NULL,
  version     INT NOT NULL,
  content     TEXT NOT NULL,
  created_by  VARCHAR(100),
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  is_active   BOOLEAN DEFAULT FALSE,
  UNIQUE KEY uk_name_version (name, version)
);
```

**2. Record the prompt version in response logs**

```python
log = {
    "prompt_name": "customer_faq",
    "prompt_version": 12,
    "question": question,
    "answer": answer,
}
```

**3. Compare before and after with a fixed question set**

I fixed a set of 30 frequently asked questions and added a step of comparing answers against the previous version whenever the prompt changes.

## Conclusion

Managing prompt history in the DB made it possible to pinpoint when a problem started and to roll back. Anything that affects behavior needs the same level of version control as code, even when it isn't code.
