Today I'll write up how I chose the embedding model for a RAG system.

## Situation

I had to build RAG over mostly Korean documents that include some English technical terms.

## Problem

I applied a top model from the leaderboard, but the quality of the actual search results fell short of expectations. The cause was that the benchmark datasets (news and general sentences) differed in character from the real data (long, formal text such as terms and conditions).

## Fix

I built my own evaluation set. For 50 real user questions, I labeled the correct chunks by hand and compared models by Recall@5.

Here is what I found.

**1. A multilingual model did better on documents that mix in English.**

**2. Embedding dimension and performance did not scale together.** The Recall@5 gap between the 1024-dimension and 384-dimension models was small, while storage and latency differed clearly.

**3. Normalization was missing.** When using cosine similarity, embeddings need to be normalized.

```python
output = model(text, pooling="mean", normalize=True)
```

## Conclusion

I ended up choosing a 384-dimension multilingual model. It ranked lower on the leaderboard but suited the real data better and cost less to run. Building my own evaluation set helped more than consulting benchmarks.
