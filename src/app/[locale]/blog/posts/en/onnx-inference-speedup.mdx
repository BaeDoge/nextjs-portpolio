Today I'll write up how I improved the inference speed of an embedding model.

## Situation

Inference took about 180ms per request, which made up a large share of the RAG pipeline's total latency. I ruled out swapping the model because of concerns about quality loss.

## Improvement 1: Batch processing

```python
embed_batch(texts, size=32)  # about 2.4 seconds for 100 items
```

Batching worked well for bulk jobs such as document indexing, but it was hard to apply to real-time queries where most requests arrive one at a time.

## Improvement 2: ONNX conversion

```python
from optimum.onnxruntime import ORTModelForFeatureExtraction

model = ORTModelForFeatureExtraction.from_pretrained(
    "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2",
    export=True,
)
model.save_pretrained("./onnx-model")
```

Single-request inference time dropped from 165ms to about 90ms.

## Improvement 3: Quantization

```python
from optimum.onnxruntime import ORTQuantizer
from optimum.onnxruntime.configuration import AutoQuantizationConfig

quantizer = ORTQuantizer.from_pretrained("./onnx-model")
config = AutoQuantizationConfig.avx512_vnni(is_static=False, per_channel=True)
quantizer.quantize(save_dir="./onnx-quantized", quantization_config=config)
```

After applying int8 quantization, latency dropped to about 55ms and the model size shrank to about a quarter. On the evaluation set I had built beforehand, the drop in Recall@5 was under 1 percentage point.

## Conclusion

In the end, latency improved from 180ms to about 70ms including tokenization. Optimizing the runtime alone, without replacing the model, produced a meaningful improvement, and the evaluation set I had built beforehand played an important role in verifying quality.
