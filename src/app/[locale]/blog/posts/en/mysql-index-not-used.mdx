Today I'll write up a case where an index existed but query performance did not improve.

## Situation

The response time of a lookup API had slowed to over three seconds. The column already had an index.

## Finding the cause

```sql
EXPLAIN SELECT * FROM chat_logs
WHERE DATE(created_at) = '2026-03-20';
```

```
type: ALL
key: NULL
rows: 2841203
```

`key` was NULL, so the index was not being used. When a function such as `DATE(created_at)` is applied to an indexed column, MySQL cannot use the index.

## Fix

I changed the condition to a range search.

```sql
SELECT * FROM chat_logs
WHERE created_at >= '2026-03-20 00:00:00'
  AND created_at <  '2026-03-21 00:00:00';
```

```
type: range
key: idx_created_at
rows: 4210
```

The response time improved from three seconds to 40ms.

## Similar patterns

Conditions like these also skip the index.

```sql
WHERE YEAR(created_at) = 2026
WHERE CAST(user_id AS CHAR) = '123'
WHERE user_id + 0 = 123
```

## Conclusion

Applying a function or type conversion to an indexed column invalidates the index. Since then, when a query gets slow, my first step is to check the `key` and `rows` values with `EXPLAIN`.
