Today I'll write up a hydration error I hit in Next.js.

## Problem

```
Hydration failed because the server rendered HTML didn't match the client.
```

The screen displayed normally, but the console repeatedly showed the error above.

## Finding the cause

Following the error message led to the date display in a post list.

```tsx
<span>{new Date(post.publishedAt).toLocaleDateString()}</span>
```

`toLocaleDateString()` follows the locale of the environment it runs in. The server (UTC/en-US) and the browser (KST/ko-KR) produced different strings, which caused the HTML mismatch.

- Server: `3/21/2026`
- Browser: `2026. 3. 21.`

## Fix

I specified the locale and time zone explicitly.

```tsx
function formatDate(iso: string) {
  return new Intl.DateTimeFormat("ko-KR", {
    timeZone: "Asia/Seoul",
    year: "numeric",
    month: "long",
    day: "numeric",
  }).format(new Date(iso));
}
```

After this change, I confirmed that the server and the client output the same result.

## Similar patterns

Hydration errors mostly happen when the server and client render different results.

```tsx
{Math.random()}
{new Date().toLocaleString()}
{typeof window !== "undefined" ? "A" : "B"}
{localStorage.getItem("theme")}
```

For values that can only be determined in the browser, I render them after mount.

```tsx
const [mounted, setMounted] = useState(false);
useEffect(() => setMounted(true), []);

if (!mounted) return null;
return <ThemeAwareThing />;
```

## Conclusion

Making sure the server and client generate the same HTML was the key to preventing hydration errors. Dates, random values, and browser-only APIs were the main causes.
