## 사건

챗봇 답변 품질이 떨어졌다는 제보가 들어왔습니다.
코드는 배포한 적이 없었습니다. 모델도 그대로였습니다.

알고 보니 누군가 관리자 화면에서 프롬프트를 수정했고,
이전 내용이 어디에도 남아 있지 않았습니다.

## 문제의 구조

프롬프트는 코드처럼 동작에 영향을 주는데, 코드처럼 관리되지 않고 있었습니다.

- 누가 바꿨는지 모름
- 뭘 바꿨는지 모름
- 되돌릴 수 없음
- 바꾸기 전후를 비교할 수 없음

## 지금 하는 방식

**1. 프롬프트를 DB에 버전으로 쌓는다**

덮어쓰지 않고 append만 합니다.

```sql
CREATE TABLE prompts (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  name        VARCHAR(100) NOT NULL,
  version     INT NOT NULL,
  content     TEXT NOT NULL,
  created_by  VARCHAR(100),
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  is_active   BOOLEAN DEFAULT FALSE,
  UNIQUE KEY uk_name_version (name, version)
);
```

활성 버전만 `is_active = TRUE`로 바꿉니다. 롤백은 플래그만 되돌리면 됩니다.

**2. 응답 로그에 버전을 남긴다**

```python
log = {
    "prompt_name": "customer_faq",
    "prompt_version": 12,
    "question": question,
    "answer": answer,
}
```

"언제부터 이상해졌나"를 물었을 때 바로 답할 수 있게 됩니다.
이게 제일 유용했습니다.

**3. 바꾸기 전에 고정 질문 세트로 돌려본다**

자주 들어오는 질문 30개를 고정해두고, 프롬프트를 바꾸면 그걸 돌려서
이전 버전 답변과 나란히 비교합니다.

자동 채점까지는 안 합니다. 사람이 훑어보는 것만으로도
"어? 이건 이상한데" 하는 게 대부분 걸립니다.

## 안 한 것

프롬프트를 git에 넣는 방법도 고민했는데, 저희는 비개발 직군도
프롬프트를 수정해야 해서 DB 쪽을 택했습니다.
개발자만 만진다면 git이 더 단순할 것 같습니다.

## 정리

"코드가 아닌데 동작을 바꾸는 것"은 전부 버전 관리 대상입니다.
프롬프트, 피처 플래그, 룰 테이블. 다 같은 문제를 갖고 있습니다.
