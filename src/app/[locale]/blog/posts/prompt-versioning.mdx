오늘은 프롬프트 버전 관리를 도입한 과정을 정리해 보겠습니다.

## 문제

챗봇 답변 품질 저하가 보고되었습니다. 코드 배포 이력이나 모델 변경 사항은 없었습니다. 확인 결과, 관리자 화면에서 프롬프트가 수정되었고 이전 버전은 별도로 저장되어 있지 않았습니다.

프롬프트가 동작에 직접적인 영향을 미침에도 변경 이력이 관리되지 않고 있었습니다.

## 해결

**1. 프롬프트를 DB에 버전 단위로 저장**

```sql
CREATE TABLE prompts (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  name        VARCHAR(100) NOT NULL,
  version     INT NOT NULL,
  content     TEXT NOT NULL,
  created_by  VARCHAR(100),
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  is_active   BOOLEAN DEFAULT FALSE,
  UNIQUE KEY uk_name_version (name, version)
);
```

**2. 응답 로그에 프롬프트 버전 기록**

```python
log = {
    "prompt_name": "customer_faq",
    "prompt_version": 12,
    "question": question,
    "answer": answer,
}
```

**3. 고정 질문 세트로 변경 전후 비교**

자주 발생하는 질문 30건을 고정하여, 프롬프트 변경 시 이전 버전과 답변을 비교하는 절차를 추가했습니다.

## 결론

프롬프트 변경 이력을 DB로 관리하면서 문제 발생 시점 파악과 롤백이 가능해졌습니다. 코드가 아니지만 동작에 영향을 미치는 요소는 동일한 수준의 버전 관리가 필요하다는 점을 확인했습니다.
