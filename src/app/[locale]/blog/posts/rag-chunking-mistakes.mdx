오늘은 RAG 시스템의 청킹 전략을 개선한 과정을 정리해 보겠습니다.

## 상황

일반적인 기준인 `chunk_size=512, overlap=50`으로 청킹을 구성했습니다. 약관과 같은 조항 기반 문서에 적용한 결과 문제가 발생했습니다.

## 문제

512 토큰 단위로 분할하면 조항의 항(①②③) 사이가 잘리는 경우가 있었습니다. 이 경우 "해지 가능"이라는 내용만 검색되고 "단, 제한 사항"에 해당하는 내용이 누락되는 문제가 발생했습니다.

## 개선 과정

**1차: overlap 확대**

`overlap=200`으로 조정했으나, 유사한 청크가 중복 검색되는 문제가 발생했습니다.

**2차: 조항 단위 분할**

```python
import re

def split_by_article(text: str) -> list[str]:
    parts = re.split(r'(제\s*\d+\s*조)', text)
    chunks = []
    for i in range(1, len(parts), 2):
        chunks.append(parts[i] + parts[i + 1])
    return chunks
```

의미 단위는 유지되었으나, 조항별 길이 편차가 커 긴 조항의 임베딩 품질이 저하되었습니다.

**최종: 2단계 분할 및 상위 제목 포함**

1. 조항 단위로 우선 분할
2. 긴 조항은 항 단위로 재분할
3. 각 청크에 상위 조항 제목을 포함

```
[제15조 (해지)] ② 제1항에도 불구하고, 다음 각 호의 경우에는...
```

## 결론

청킹 기준을 토큰 수가 아닌 문서의 의미 단위로 설정한 것이 검색 정확도 개선에 효과적이었습니다. 문서 유형에 따라 적절한 청킹 기준은 달라질 수 있습니다.
