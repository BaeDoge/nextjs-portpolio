오늘은 Tailwind와 CSS Modules를 함께 사용하며 정리한 기준을 공유해 보겠습니다.

## 배경

포트폴리오 프로젝트에서 두 방식을 함께 사용하게 되면서, 각 방식이 적합한 상황을 정리했습니다.

## Tailwind가 적합한 경우

**단순 레이아웃**

```tsx
<div className="flex items-center gap-2 px-4 py-2 rounded-lg">
```

**반응형 처리**

```tsx
<div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3">
```

별도의 미디어 쿼리 작성 없이 처리할 수 있었습니다.

## CSS Modules가 적합한 경우

**상태가 많은 컴포넌트**

hover, focus, disabled 등 여러 상태가 조합되는 경우 클래스 문자열이 길어져 가독성이 떨어졌습니다.

```css
.button:disabled {
  background: var(--gray-200);
  cursor: not-allowed;
}
```

**애니메이션**

keyframes가 포함된 스타일은 CSS 파일로 관리하는 것이 효율적이었습니다.

## 적용 기준

- 레이아웃, 간격, 정렬 → Tailwind
- 컴포넌트 고유 스타일, 상태 변화, 애니메이션 → CSS Modules
- 색상 값은 CSS 변수로 공유

색상 값을 공유하지 않으면 다크모드 적용 시 값이 불일치하는 문제가 있어, 아래와 같이 변수를 공통으로 참조하도록 했습니다.

```css
:root {
  --surface: #ffffff;
}
@media (prefers-color-scheme: dark) {
  :root { --surface: #121212; }
}
```

## 결론

두 방식 중 하나를 선택하기보다 적용 범위를 명확히 구분하는 것이 유지보수 측면에서 효율적이었습니다.
