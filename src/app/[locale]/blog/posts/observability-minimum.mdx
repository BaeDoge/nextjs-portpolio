## 시작은 의욕이었다

관측 가능성을 제대로 해보자고 대시보드를 잔뜩 만들었습니다.
CPU, 메모리, 네트워크, 디스크 IO, GC, 커넥션 풀...

한 달 뒤, 장애가 났을 때 제가 실제로 연 대시보드는 하나였습니다.

## 실제로 쓴 것

**1. 에러율**

```
5xx 응답 수 / 전체 요청 수
```

가장 먼저 보게 됩니다. 이게 정상이면 대부분 정상입니다.

**2. p95 지연**

평균은 쓸모가 없었습니다.
평균 200ms인데 일부 사용자가 5초를 겪고 있어도 평균에는 안 드러납니다.

p95, p99를 보면 "일부가 느린" 상황이 바로 보입니다.

**3. 처리량**

요청 수가 갑자기 0이 되거나 평소의 10배가 되면 뭔가 잘못된 겁니다.
절대값보다 **평소 대비 변화**를 봅니다.

## 지운 것

CPU와 메모리 그래프를 지웠습니다. 의외일 수 있는데,
이것들이 문제라면 위 세 개에 먼저 나타납니다.

CPU가 80%여도 응답이 빠르면 문제가 아닙니다.
반대로 CPU가 30%인데 응답이 느리면 그건 CPU 문제가 아닙니다.

## 알림도 줄였다

알림이 하루에 수십 개 오던 때가 있었습니다.
그러면 아무도 안 봅니다. 저도 안 봤습니다.

기준을 바꿨습니다: **"이 알림이 오면 지금 바로 무언가 해야 하는가?"**

아니라면 알림이 아니라 대시보드에 있어야 할 정보입니다.
이 기준으로 거르니 알림이 하루 1~2개로 줄었고, 그제서야 보게 됐습니다.

## 지금

나중에 필요해지면 그때 추가하기로 했습니다.
미리 만들어둔 대시보드는 대부분 필요할 때 기억나지 않았습니다.
