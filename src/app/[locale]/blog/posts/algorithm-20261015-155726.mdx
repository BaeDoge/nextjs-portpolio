## 문제

두 개의 서로 다른 정수 배열 nums1과 nums2가 주어지며, nums1은 nums2의 부분집합입니다. nums1의 각 원소에 대해 nums2에서 해당 원소가 위치하는 인덱스 오른쪽에 있는 첫 번째로 큰 값을 찾아야 합니다. 만약 오른쪽에 더 큰 값이 없다면 -1을 반환합니다. 최종적으로 nums1의 각 원소에 대한 결과를 배열로 반환합니다. 모든 원소는 고유하며, nums1의 원소는 반드시 nums2에 존재합니다.

## 접근 방법

nums1의 각 원소를 nums2에서 찾아 오른쪽을 탐색하는 방식은 비효율적입니다. 대신 nums2를 한 번만 순회하며 각 원소의 '다음 큰 수'를 미리 계산해 해시맵에 저장하는 전략을 사용합니다. 이를 위해 스택을 활용하여 현재 원소보다 작은 이전 원소들을 관리합니다. nums2를 순회할 때, 현재 원소가 스택의 최상단 원소보다 크다면 스택에서 꺼낸 원소의 다음 큰 수가 현재 원소임을 의미합니다. 이 관계를 해시맵에 기록하면 nums1의 각 원소에 대한 조회는 O(1) 시간에 가능합니다.

## 풀이

먼저 빈 해시맵과 스택을 초기화합니다. nums2의 각 원소를 순회하며 스택이 비어 있지 않고, 현재 원소가 스택의 최상단 원소보다 큰 경우 반복문을 실행합니다. 이 조건이 성립하면 스택에서 원소를 pop하고, pop된 원소를 키로, 현재 원소를 값으로 하는 매핑을 해시맵에 추가합니다. 이후 현재 원소를 스택에 push합니다. nums2 순회가 끝나면, nums1의 각 원소를 해시맵에서 조회하여 결과를 배열에 저장합니다. 해시맵에 해당 키가 없는 경우(즉, 다음 큰 수가 없는 경우)는 -1을 사용합니다.

```python
def nextGreaterElement(nums1, nums2):
    stack = []
    next_greater_map = {}
    
    for num in nums2:
        while stack and stack[-1] < num:
            prev = stack.pop()
            next_greater_map[prev] = num
        stack.append(num)
    
    result = []
    for num in nums1:
        result.append(next_greater_map.get(num, -1))
        
    return result
```

시간복잡도: O(N + M)입니다. 여기서 N은 nums2의 길이, M은 nums1의 길이입니다. nums2의 각 원소는 최대 한 번 스택에 push되고 한 번 pop되므로 선형 시간 내에 처리됩니다. nums1의 조회는 O(1)이므로 전체적으로 선형 시간입니다. 공간복잡도: O(N)입니다. 스택과 해시맵은 최대 N개의 원소를 저장할 수 있습니다.

## 다른 풀이 방법

완전 탐색 방식이 있습니다. nums1의 각 원소에 대해 nums2에서 해당 원소의 인덱스를 찾고, 그 인덱스부터 오른쪽으로 순회하며 더 큰 값을 찾습니다. 이 경우 nums1의 길이 M, nums2의 길이 N일 때 시간복잡도는 O(M * N)이 됩니다. 모노톤 스택 방식에 비해 훨씬 느리며, 제약 조건에서 N이 1000 이하이므로 통과할 수 있지만 확장성이 떨어집니다. 해시맵을 사용하지 않고 스택만 사용하는 변형도 존재하지만, 결국 다음 큰 수를 매핑해야 하므로 해시맵 또는 배열을 통한 저장소는 필요합니다.

## 추가 참고사항

이 문제는 'Next Greater Element' 시리즈의 첫 번째로, 모노톤 스택(Monotonic Stack) 기법의 대표적인 예시입니다. 스택에 내림차순으로 원소를 유지하면서 현재 원소와의 비교를 통해 '다음 큰 수'를 찾는 패턴은 다양한 배열 문제에서 활용됩니다. nums2의 원소가 중복되지 않는다는 제약 조건 덕분에 해시맵의 키로 원소 값을 직접 사용할 수 있어 구현이 단순해집니다. 만약 원소가 중복된다면 인덱스를 키로 사용하거나 별도 처리가 필요합니다.
