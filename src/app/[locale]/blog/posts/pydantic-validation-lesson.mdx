## 사건

전화번호 형식 검증이 프론트, API, 배치 세 곳에 각각 있었습니다.
규칙이 바뀌어서 API만 고치고 배포했더니, 배치에서 넣은 데이터가 조회에서 걸러졌습니다.

## 왜 흩어졌나

각각 이유는 있었습니다.

- 프론트: 사용자에게 즉시 피드백을 주려고
- API: 외부 호출을 막으려고
- 배치: CSV 업로드를 검증하려고

문제는 **규칙 자체가 복사돼 있었다**는 점입니다.

## 바꾼 방식

규칙을 한 곳에 모으고, 나머지는 그걸 호출만 하게 했습니다.

```python
# validators.py — 단일 출처
from pydantic import BaseModel, field_validator
import re

PHONE_RE = re.compile(r"^01[016789]-?\d{3,4}-?\d{4}$")

class Contact(BaseModel):
    phone: str

    @field_validator("phone")
    @classmethod
    def check_phone(cls, v: str) -> str:
        normalized = v.replace("-", "")
        if not PHONE_RE.match(v):
            raise ValueError("전화번호 형식이 올바르지 않습니다")
        return normalized
```

API와 배치는 이 모델을 그대로 씁니다.
프론트는 별도 언어라 어쩔 수 없이 중복인데, 정규식 문자열만
빌드 시점에 공유 상수로 내려주도록 했습니다.

## 부수 효과 — 정규화

검증만 하던 걸 **검증 + 정규화**로 바꾼 게 의외로 컸습니다.

전에는 `010-1234-5678`과 `01012345678`이 DB에 섞여 있었습니다.
조회할 때마다 두 형태를 다 고려해야 했습니다.

이제 저장 직전에 하이픈을 제거하므로 DB에는 한 형태만 들어갑니다.

## 원칙

- 검증 규칙은 **한 곳**에만 정의한다
- 여러 곳에서 필요하면 **호출**하지 복사하지 않는다
- 검증하면서 정규화까지 한다

세 번째가 특히 나중에 많은 걸 막아줬습니다.
